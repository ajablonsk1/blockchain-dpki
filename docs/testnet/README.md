# DPKI Local Testnet

A 4-validator BFT testnet, runnable either as local processes or in Docker.
Everything is reproducible with two commands; no manual config editing.

## Quick start (local processes)

```bash
make build
./bin/dpkid testnet init                 # generates ./testnet-data/node0..node3
./scripts/start-testnet.sh --no-verify   # start all validators in the background
./scripts/stop-testnet.sh                # stop them
```

`--no-verify` disables DNS-01 ownership checks so test domains can be
registered without publishing real TXT records; omit it to enforce them.

Send transactions and read state with the regular CLI:

```bash
./bin/dpki-cli keys generate --output key.priv
./bin/dpki-cli register --domain example.com --keyfile key.priv --skip-challenge
./bin/dpki-cli verify --domain example.com \
    --nodes http://localhost:26657,http://localhost:26667,http://localhost:26677,http://localhost:26687
```

## Quick start (Docker)

```bash
./bin/dpkid testnet init --docker --output-dir ./testnet-docker
docker compose up --build
```

The same RPC ports are published on the host, so all `dpki-cli` commands work
unchanged.

## Topology

```
┌─────────┐    ┌─────────┐
│ node0   │◄──►│ node1   │
│ :26657  │    │ :26667  │
└────┬────┘    └────┬────┘
     │   full mesh  │
     │  (P2P 2665X) │
┌────▼────┐    ┌────▼────┐
│ node3   │◄──►│ node2   │
│ :26687  │    │ :26677  │
└─────────┘    └─────────┘
```

- 4 validators, equal voting power (10 each), full-mesh `persistent_peers`.
- Node `i`: RPC on `26657 + 10i`, P2P on `26656 + 10i` (local mode); in Docker
  every container uses the default ports and host port `26657 + 10i` maps to it.
- One shared genesis (byte-identical in every home), unique validator and node
  keys per home — both generated by `dpkid testnet init` (no `cometbft` binary
  needed).

## Fault tolerance

CometBFT tolerates `f` Byzantine validators out of `n = 3f + 1`. With `n = 4`,
`f = 1`:

| Validators alive | Voting power | Consensus                          |
|------------------|--------------|------------------------------------|
| 4/4              | 100%         | blocks every ~1s                   |
| 3/4              | 75% > 2/3    | blocks continue, writes accepted   |
| 2/4              | 50% < 2/3    | **halted** — safety over liveness  |
| restart to 4/4   | 100%         | nodes replay + blocksync, resume   |

App state is in-memory; a restarted validator rebuilds it deterministically by
replaying committed blocks through `FinalizeBlock` (ADR 023), then catches up
via blocksync and rejoins consensus.

## Test harness

```bash
./scripts/test-testnet.sh
```

Runs six scenarios and saves their transcripts to `docs/testnet/logs/`
(empirical material for the thesis):

1. `test-1-block-production` — all 4 validators reach height ≥ 3.
2. `test-2-state-replication` — a RegisterTx sent to node0 is readable and
   provable (`verify` 4/4) on every node.
3. `test-3-determinism` — 50 transactions round-robin across nodes; the header
   app hash at one common height is identical on all validators.
4. `test-4-one-node-failure` — node0 killed; heights keep advancing and a
   write through node1 commits.
5. `test-5-two-node-failure` — node1 also killed; height frozen for 15s
   (consensus halt with <2/3 power).
6. `test-6-recovery` — both nodes restarted; they replay, sync, consensus
   resumes and all 4 app hashes match again.
